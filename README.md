# DSC Document Tool

정격하중표(Rated Load Chart) 문서를 만드는 브라우저 기반 도구입니다. 빌드 과정 없이 동작하는 정적 웹앱이라 GitHub Pages에 그대로 올려 쓸 수 있습니다.

- **이 저장소에는 프로그램 코드만 들어 있습니다.** 실제 기종 데이터는 넣지 않습니다.
- 두 가지 방식으로 동작합니다 (`app/config.js`의 `API_URL`).
  - **웹 모드**: 구글 시트 '개발 DATABASE'에 붙인 Apps Script(`gas/Code.gs`)를 서버로 씁니다. 제품 분류·사용자 명단은 구글 시트에서 관리하고, 정격하중 데이터·로고는 관리자 구글 드라이브에, 이력은 시트의 '이력' 탭에 남습니다. 설정 방법: [docs/WEB-SETUP.md](docs/WEB-SETUP.md)
  - **로컬 모드** (`API_URL` 비움): 데이터가 사용하는 브라우저 안(IndexedDB)에만 저장됩니다.

## 화면 구성

오른쪽 위 토글로 **사용자**와 **관리자** 화면을 전환합니다.

### 사용자 (`#/`)

한 페이지에 **제품 선택** · **조회** · **PDF 생성** 구역이 위에서 아래로 이어집니다.
구성(제품명 · Sub Winch · Sub Boom)을 모두 고르면 아래의 조회 · PDF 생성 구역이 채워집니다.

- **제품 선택**: 검색창과 필터 드롭다운((분류) → ① 제품명 → ② Sub Winch → ③ Sub Boom)으로 구성을 고릅니다.
  - 목록은 관리자 화면에서 가져온 **제품 DB**(엑셀: No. · 분류 · 제품명 · Sub Winch · Sub Boom)를 따릅니다.
  - 제품 DB가 없으면 등록된 정격하중 데이터로 목록을 만듭니다 (Sub Winch = 없음 + 보조 윈치 용량, Sub Boom = 없음 + S/B 길이).
  - 정격하중표는 제품명 = 기종명으로 연결됩니다. 데이터가 없는 제품은 '미등록'으로 표시되고 조회할 수 없습니다.
- **조회**: 선택한 구성에 맞춘 정격하중표를 작업영역 · 아우트리거 · 윈치 버튼으로 골라 봅니다.
  - Sub Winch가 '없음'이면 보조 윈치 표를 빼고 보여 줍니다.
  - Sub Boom이 '없음'이면 S/B 열을 빼고 보여 줍니다.
- **PDF 생성**: 제공처·관리번호를 넣어 고객 제공용 PDF를 만듭니다.
  - 표지와 머리글에 적용 사양이 표시되고, 파일명에 사양 태그가 붙습니다.
  - 검증 NG가 남은 데이터는 확인 체크를 해야 만들 수 있습니다.

### 관리자 (`#/admin`)

1. **기종 목록**: 새 기종을 만들거나, 기존 정격하중표 엑셀을 가져오거나, 백업 파일(JSON)을 엽니다.
   - **제품 DB**: 사용자 화면 제품 목록의 기준 엑셀을 가져옵니다. 엑셀을 고친 뒤 '다시 가져오기'로 갱신합니다. 제품별 정격하중 데이터 등록 여부가 함께 보입니다.
   - **보안관리** (`#/admin/security`): 사용자 명단(사번 · 이름 · 관리자)을 엑셀(개발 DATABASE 파일의 '사용자' 시트: 사번 · 이름 · 관리자 권한 O)에서 가져오거나 직접 추가합니다. 웹 모드에서는 명단을 구글 시트 '사용자' 탭에서 고치고, 이 화면은 확인용(읽기 전용)입니다.
     - 명단이 있으면 도구를 열 때마다 진입 화면이 나옵니다: 사번(숫자 + 기본 뒷자리 HA) → 이름 초성을 순서대로 입력(예: 홍길동 → ㅎㄱㄷ, 확인 단계). 명단에 없는 사번은 다음 단계로 넘어가지 않습니다. 초성이 맞으면 바로 들어가고, 다르면 오류를 띄우고 사번부터 다시 시작합니다(진입 실패도 이력에 남습니다).
     - 들어오면 상단에 '사번 이름 님 조회중'이 표시되고, 관리자로 지정된 사람만 관리자 화면에 들어갈 수 있습니다.
     - 진입 · 종료 · 제품 조회 · PDF 생성 이력이 사번 · 이름과 함께 남고, 보안관리 화면에서 찾아보거나 CSV로 내려받습니다.
     - 명단과 이력은 이 브라우저에만 저장되며 저장소에는 들어가지 않습니다. 명단이 없으면 보안관리는 꺼져 있습니다.
     - 브라우저 안에서만 동작하는 기록·확인 장치이므로, 개발자 도구를 다룰 줄 아는 사람을 막는 강제 보안은 아닙니다.
   - **회사 로고 (CI)**: 모든 화면 맨 위에 표시할 로고(PNG/JPG)를 등록합니다. 저장소가 공개라서 로고 파일은 저장소에 넣지 않고 이 브라우저에만 저장합니다. 등록하지 않으면 'DY' 글자로 표시합니다.
   - 이미 있는 기종을 다시 가져오면 '데이터 교체(문서 정보 유지)' 또는 '새로 추가'를 고릅니다.
   - 엑셀은 **시트 하나 = 보조 윈치 용량 하나**로 읽습니다. 메인 윈치는 첫 시트 값을 씁니다.
   - 가져오기 화면에서 시트별 보조 윈치 용량을 확인·수정합니다. 시트 이름에 '4ton' 같은 표기가 있으면 자동으로 채웁니다.
2. **초기 설정**: 아래 항목을 입력하면 입력 양식이 자동으로 만들어집니다.
   - 문서 정보, 작업반경 범위
   - 붐 단수·붐 길이·최대 작업반경
   - 보조 윈치: 용량별로 여러 개 등록 (예: 3 ton, 4 ton). 각각 붐 길이·S/B·하중 표를 따로 가집니다.
   - 메인 윈치 표는 하나입니다 (보조 윈치 용량과 무관).
   - 줄걸이 기준 하중, 작업영역(각도), 아우트리거 단계
3. **하중 입력**: 엑셀처럼 생긴 표에 입력합니다. 엑셀에서 범위를 복사해 붙여넣을 수 있습니다.
   - 붙여넣기: Ctrl+V
   - 범위 선택: Shift+방향키 또는 드래그
   - 범위 복사·지우기: Ctrl+C, Delete
   - 되돌리기: Ctrl+Z
   - `(8.1)`처럼 괄호로 쓰면 최대반경 표기로 처리됩니다.
4. **검증**: 아래 항목을 자동으로 점검합니다. 결과에서 해당 칸으로 바로 이동할 수 있습니다.
   - 반경이 커지는데 하중이 증가하는 칸
   - 아우트리거·작업영역 간 대소 관계
   - 입력 오류, 최대반경 표기
5. **PDF**: 고객 제공용(제공처·관리번호 워터마크) 또는 내부용(변동구간·NG 표시) PDF를 브라우저 안에서 만듭니다.
   - 보조 윈치가 있는 기종은 적용 사양(Sub Winch·Sub Boom)을 골라 문서 하나에 보조 윈치 한 가지만 넣습니다.

## 이 PC에서 실행

`run-local.bat`을 더블클릭하면 http://127.0.0.1:8765 이 열립니다. Python이 설치되어 있어야 합니다.

- 서버(`tools/serve.py`)가 브라우저 캐시를 끄므로, 코드가 바뀌어도 **새로고침(F5)만 하면 됩니다**.
- 서버가 이미 실행 중이면 브라우저만 엽니다.

브라우저 저장소는 주소(origin)별로 나뉩니다. 로컬 주소와 GitHub Pages 주소 사이에서 데이터를 옮길 때는 **백업 저장 → 백업 파일 열기**를 쓰세요.

## 개발용 테스트 (Node 18+)

실데이터 파일은 저장소 밖에 두고 경로만 넘깁니다.

```
node tests/import-check.mjs  <정격하중표.xlsx> [모델.json]   # 가져오기 + 검증 요약
node tests/markers-check.mjs <정격하중표.xlsx>                # 최대반경 자동 표기 재현 확인
node tests/pdf-build.mjs     <정격하중표.xlsx|모델.json> <출력.pdf> [customer|internal] [제공처] [관리번호]
```

## 구성

| 경로 | 내용 |
|---|---|
| `app/core/` | 데이터 모델, 검증, xlsx 읽기, 기존 엑셀 양식 가져오기 (DOM 없음 — Node에서도 동작) |
| `app/pdf/` | PDF 생성(pdf-lib), 작업영역·아우트리거 그림 |
| `app/ui/` | 화면 (기종 목록, 초기 설정, 하중 입력, 검증, PDF) |
| `app/storage/` | 저장소 (현재 로컬 IndexedDB) |
| `vendor/`, `fonts/` | pdf-lib, fontkit(로컬 패치 1건), Pretendard 폰트 — 라이선스는 `vendor/README.md` |
